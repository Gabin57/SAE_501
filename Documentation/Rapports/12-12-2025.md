# Rapport d'Avancement - 12 Décembre 2025

## 1. Résumé Exécutif
Ce rapport détaille les interventions techniques réalisées sur la journée du 11 Décembre (anticipé au 12) pour stabiliser l'architecture client-serveur (Flutter/Python) et améliorer l'expérience utilisateur. L'objectif principal de rétablir la communication API et de rendre l'application accessible depuis des terminaux externes a été atteint.

## 2. Interventions Techniques

### 2.1. Back-end (API Python)
**Diagnostic :**
L'API refusait de démarrer et consommait 100% du CPU, entrant dans une boucle de redémarrage infinie gérée par `systemd`. L'analyse des logs (`app.log`) a révélé des erreurs critiques bloquantes empêchant l'interprétation du code.

**Actions Correctives :**
- **Correction Syntaxique Critique** : Identification et rectification d'une erreur de syntaxe dans `prepare_dataset.py` (ligne 96), où une accolade fermante prématurée et une virgule manquante brisaient la structure du dictionnaire principal de configuration.
- **Correction de Chemin** : Rectification d'une faute de frappe dans `app.py` (`Database.images` remplacé par `Database/images`), prévenant une erreur de type `FileNotFoundError` lors du chargement des datasets d'entraînement.
- **Validation** : Le service redémarre désormais normalement et écoute sur le port **5001** (`0.0.0.0`).

### 2.2. Infrastructure & Réseau
**Problème :**
L'application Flutter, bien que démarrée, était inaccessible depuis l'extérieur ("Connection Timed Out" / "Site inaccessible"), bloquant les tests sur mobile.

**Actions Correctives :**
- **Pare-feu (UFW)** : Le port 8080 était bloqué par la politique de sécurité par défaut du serveur. Une règle explicite `allow 8080/tcp` a été ajoutée.
- **Vérification** : La commande `ss -tulpn` confirme que les services écoutent sur toutes les interfaces (`0.0.0.0`), garantissant l'accessibilité réseau depuis n'importe quel appareil sur le même réseau.

### 2.3. Front-end (Application Flutter)
**Compatibilité Web :**
- **Problème `dart:io`** : L'application plantait sur navigateur car elle tentait d'accéder au système de fichiers local via la classe `File`, une opération interdite dans un contexte Web (`Unsupported operation: _Namespace`).
- **Solution** : Implémentation d'une logique conditionnelle stricte (`if (!kIsWeb)`) pour utiliser exclusivement des URLs réseaux sur le web et réserver l'accès fichiers aux versions natives.

**Affichage et Médias :**
- **Support SVG** : L'API renvoyant des fichiers au format `.svg`, l'application échouait à les afficher (format non supporté nativement par `Image.network`). La dépendance `flutter_svg` a été intégrée au projet (`pubspec.yaml`) et le code adapté pour utiliser `SvgPicture.network` lors de la détection de cette extension.
- **Optimisation UI** :
  - **Mise à l'échelle** : Passage du mode d'affichage de `cover` (qui rognait les bords) à `contain` pour garantir que l'intégralité du panneau signalétique est visible.
  - **Espacement** : Ajout de padding (16.0) autour des images pour aérer la grille.
  - **Typographie** : Les titres trop longs sont maintenant tronqués proprement avec des points de suspension (...) après 2 lignes (`TextOverflow.ellipsis`), préservant l'alignement vertical des cartes.

## 3. État Actuel
- **API** : Opérationnelle, stable, écoute sur 5001.
- **Client Web** : Opérationnel, accessible sur le port 8080 depuis mobile et desktop via IP publique.
- **Stabilité** : Plus de crash au démarrage ni d'erreurs de rendu d'images.
